# Сканер вилок

Веб-приложение для автоматического поиска **двухисходных вилок** только по реальным данным пяти БК: **Winline, BetBoom, Fonbet, Liga Stavok, bc.game**. Демо-режима нет — сканер работает исключительно с настоящей линией.

Сканер работает **только с прематчем** (live отключён). Проверяются все прематч-события, включая дочерние росписи (тайму, сеты, периоды), и **любые рынки ровно с двумя исходами**:

- **Победитель** — П1 / П2 (рынки с ничьей отбрасываются);
- **Тоталы больше/меньше** — голов, очков, геймов, сетов, а также углов, жёлтых карт, фолов, эйсов, ударов и прочей статистики;
- **Форы** (гандикапы) — Ф1 / Ф2 с любой линией;
- **Обе забьют** — Да / Нет (Winline, Fonbet, BetBoom);
- **Индивидуальные тоталы** — тотал ОДНОЙ команды (ИТБ/ИТМ), вся лестница линий обеих команд, включая таймы/периоды/сеты (Winline, Fonbet, BetBoom). Исход привязан к имени команды, поэтому рынок сшивается даже при перевёрнутом порядке команд у другой БК;
- **Чет/Нечет** — чётность тотала матча, таймов и периодов (Winline, BetBoom).

В теннисе (и других сет-видах: настольный теннис, волейбол, бадминтон) рынки **по геймам** и **по сетам** считаются раздельно: «Тотал 22.5» (геймы) и «Тотал 2.5 (сеты)» — это разные рынки, они не сшиваются между собой. Сет-тоталы и сет-форы (Winline ↔ Fonbet ↔ BetBoom) подписаны «(сеты)», чтобы их нельзя было спутать с рынком по геймам. Пары сет-фор Fonbet ориентированы по-разному (2424 — линия первого игрока, 2421 — второго) — это сверено с ориентированным рынком BetBoom на живых матчах, иначе появлялись бы ложные вилки на 10-20 %.

Каждый рынок сравнивается только с **точно таким же** рынком у других БК: тот же тип, тот же предмет (голы ≠ угловые ≠ карты), та же линия и та же часть матча (тайм/сет/период). Форы дополнительно сшиваются по команде и знаку линии — Ф1(−1.5) одной БК с Ф2(+1.5) другой, а рынки с разным фаворитом не смешиваются. Так исключаются ложные вилки. Счётчик проверенных событий и котировок виден прямо на сайте.

## Как это работает

1. Парсеры циклически собирают со всех 4 БК коэффициенты по всем двухисходным прематч-рынкам (полный круг занимает несколько минут — динамические сайты рендерятся браузером, лента каждой страницы прокручивается до конца, чтобы собрать ВСЕ матчи, а не только верхушку).
2. Котировки каждой БК **живут между циклами**: если очередной обход БК сорвался, её матчи не пропадают (хранятся до `ODDS_TTL`, по умолчанию 30 минут). Матч, который уже начался, убирается из списка автоматически по времени старта.
3. Для каждого рынка перебираются **все комбинации пар БК**: кэф исхода 1 у одной БК × кэф исхода 2 у другой.
4. Выводится **каждая** комбинация с `1/К1 + 1/К2 < 1` — не только пара с максимальными кэфами. Если тот же рынок даёт вилку и через BetBoom (кэф 1.7), и через bc.game (кэф 1.6), в таблице будут обе строки.
5. Для найденных вилок считается доходность в % и суммы ставок при банке 1 000 / 5 000 / 10 000 ₽ (выигрыш одинаковый при любом исходе).

Пример (тотал убийств в Dota): `ТБ 2.5 = 2.30 (BetBoom)`, `ТМ 2.5 = 1.85 (Winline)` → `1/2.30 + 1/1.85 = 0.9753` → доходность **2.53 %**, при банке 1 000 ₽ ставки **446 ₽ (на ТБ) / 554 ₽ (на ТМ)**.

> **Важно.** Сайты БК доступны только с **российских IP** и защищаются от парсинга. Запускать сканер нужно с машины/VPS с российским IP, иначе котировок не будет (счётчик покажет 0 событий). Fonbet работает через стабильный JSON-API, Winline и BetBoom — через прямые websocket-фиды линии (без браузера). Лига Ставок закрыта анти-ботом **Qrator**: он пропускает только «жилые» российские IP, с IP дата-центров (даже российских хостингов) JS-челлендж отклоняется и БК отдаёт 0 котировок — это ограничение самого сайта, а не парсера.

## Возможности

- Таблица вилок: время начала, спорт, матч, рынок (Победитель / Тотал X.X), исходы с их макс. кэфами и БК, доходность %, суммы ставок и прибыль для выбранного банка.
- **Кнопка «Поставить»** у каждой вилки открывает окно быстрой ставки: вводите общую сумму — сканер считает, сколько поставить на каждое плечо и какая будет прибыль, а кнопка «Открыть обе БК» открывает **страницы именно этого матча** на сайтах обеих БК в новых вкладках (суммы копируются в буфер одним кликом). Останется кликнуть нужный кэф и вставить сумму в купон. Ссылки на матч собираются для Winline (`winline.ru/stavki/event/<id>`), Fonbet (`fon.bet/sports/<вид>/<лига>/<id>`) и BetBoom (`betboom.ru/sport/<вид>/<категория>/<турнир>/<id>`). Полностью автоматическое размещение ставок не делается: для него нужны логины/пароли от аккаунтов БК, а автоматику и вилочников БК активно банят с конфискацией средств.
- На странице котировок матча каждый кэф — ссылка на страницу этого события у соответствующей БК.
- Вкладки «Матчи» и «Лайв-матчи» — **все найденные события всех видов спорта** (футбол, теннис, киберспорт и т.д.) с датами, сгруппированные по матчу. Клик по матчу открывает страницу **всех его котировок**: П1/П2, тоталы и форы по всем линиям, роспись по таймам/периодам/картам, ЖК, угловые и т.д. — кэфы всех БК бок о бок.
- Букмекеры раскрашены фирменными цветами: **Fonbet — красный, BetBoom — синий, Winline — оранжевый**, Лига Ставок — зелёный, bc.game — фиолетовый.
- **Сортировка по любому столбцу** (клик по заголовку), поиск по командам/турнирам, фильтры по виду спорта и БК, фильтр по минимальной доходности. Настройки запоминаются в браузере.
- Матчи не «слетают» при новом круге проверки: котировки живут между циклами, начавшиеся матчи убираются автоматически.
- Звуковое уведомление при появлении новой вилки с доходностью > 2.5 % (порог настраивается).
- История всех найденных вилок в SQLite (`GET /api/history`).
- Защита от блокировок: ротация User-Agent, случайные задержки 2–5 секунд между запросами к одной БК, падение одной БК не останавливает сканер.

## Быстрый запуск на своём компьютере

Нужен Python 3.10 или новее.

```bash
git clone https://github.com/filippin4ik-dev/bet.git
cd bet
pip install -r requirements.txt
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Открыть в браузере: http://localhost:8000

Сканер сразу начинает парсить реальную линию БК. С не-российского IP котировок не будет (в шапке будет «Проверено: 0 событий») — это ограничение самих БК, а не приложения.

## Развёртывание на VPS (Ubuntu 22.04 / 24.04)

> Берите VPS с **российским IP** — сайты БК доступны только из РФ.

### Шаг 1. Подключиться к серверу и поставить зависимости

```bash
ssh root@IP_ВАШЕГО_СЕРВЕРА

apt update && apt upgrade -y
apt install -y python3 python3-venv python3-pip git nginx chromium-browser
```

> `chromium-browser` нужен только для Лиги Ставок — это динамический сайт (SPA), его линию нельзя получить обычным HTTP-запросом, только через браузер (Selenium). Fonbet работает через JSON-API, а Winline и BetBoom — через прямые websocket-фиды линии (`pip install websocket-client`), браузер им не нужен. Если пакет называется иначе, попробуйте `apt install -y chromium` или `snap install chromium`.

### Шаг 2. Скачать проект и установить пакеты

```bash
mkdir -p /opt/arb-scanner
git clone https://github.com/filippin4ik-dev/bet.git /opt/arb-scanner
cd /opt/arb-scanner

python3 -m venv venv
venv/bin/pip install -r requirements.txt
```

### Шаг 3. Диагностика: проверить, что БК вообще отдают данные

Перед запуском сайта прогоните диагностику — она покажет ваш IP и страну, доступность Selenium и сколько котировок реально отдаёт каждая БК:

```bash
cd /opt/arb-scanner
venv/bin/python -m app.diagnose
```

Что означают результаты:

- **страна не RU** — сайты БК почти наверняка вернут 0. Нужен VPS с российским IP.
- **Selenium недоступен** — Лига Ставок вернёт 0 (это SPA, без браузера её не спарсить). Проверьте, что установлены `chromium-browser` и пакет `selenium`. Winline и BetBoom браузер не используют — если они отдают 0, проверьте `pip install websocket-client` и доступность фидов линии (`wss://wss.winline.ru`, `wss://ru-ws2.sporthub.bet`).
- **Fonbet: 0** при рабочем IP — сменился домен линии. Откройте `https://fon.bet` в браузере, во вкладке Network найдите запрос `events/list` или `events/listBase`, скопируйте его хост (например `line01w.bk6bba-resources.com`) и задайте переменную окружения `FONBET_LINE_HOST` (см. ниже).

### Шаг 4. Проверить веб-интерфейс

```bash
cd /opt/arb-scanner
venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Открыть `http://IP_СЕРВЕРА:8000` — при российском IP появится таблица с вилками. Остановить: `Ctrl+C`.

### Шаг 5. Автозапуск через systemd

Готовый юнит лежит в `deploy/arb-scanner.service`. Установка:

```bash
chown -R www-data:www-data /opt/arb-scanner
cp deploy/arb-scanner.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now arb-scanner
```

Проверить состояние и логи:

```bash
systemctl status arb-scanner
journalctl -u arb-scanner -f
```

Период сканирования, порог звука и прочее меняются в секции `Environment=` файла `/etc/systemd/system/arb-scanner.service`, после правки:

```bash
systemctl daemon-reload && systemctl restart arb-scanner
```

### Шаг 6. Nginx — доступ по 80-му порту

Готовый конфиг лежит в `deploy/nginx.conf`:

```bash
cp deploy/nginx.conf /etc/nginx/sites-available/arb-scanner
# впишите свой домен в server_name (или удалите строку, если доступ по IP)
nano /etc/nginx/sites-available/arb-scanner

ln -s /etc/nginx/sites-available/arb-scanner /etc/nginx/sites-enabled/
rm -f /etc/nginx/sites-enabled/default
nginx -t && systemctl reload nginx
```

Теперь сайт доступен по `http://IP_СЕРВЕРА` (без порта).

### Шаг 7. Файрвол (рекомендуется)

```bash
apt install -y ufw
ufw allow OpenSSH
ufw allow 'Nginx Full'
ufw enable
```

### Шаг 8 (по желанию). HTTPS с бесплатным сертификатом

Если есть домен, направленный на сервер:

```bash
apt install -y certbot python3-certbot-nginx
certbot --nginx -d ваш-домен.ru
```

### Обновление до свежей версии

```bash
cd /opt/arb-scanner
git pull
venv/bin/pip install -r requirements.txt
systemctl restart arb-scanner
```

| Переменная | По умолчанию | Описание |
|---|---|---|
| `SCAN_INTERVAL` | `30` | Пауза между циклами обновления, сек (сам цикл занимает несколько минут) |
| `ODDS_TTL` | `1800` | Сколько секунд держать котировки БК, если её обход сорвался (матчи не «слетают») |
| `BK_TZ_OFFSET` | `3` | Часовой пояс, в котором БК показывают время начала (МСК = 3) |
| `SCROLL_SECONDS` | `25` | Сколько секунд максимум прокручивать ленту SPA, чтобы дорисовались все матчи |
| `WINLINE_PLUS_ENABLED` | `1` | Выкачивать полную роспись каждого события Winline («event.plus»: все линии тоталов/фор, таймы, периоды); `0` — только топ-линии снапшота |
| `WINLINE_PLUS_RATE` | `15` | Сколько запросов полной росписи Winline слать в секунду |
| `WINLINE_PLUS_REFRESH` | `300` | Раз в сколько секунд обновлять полную роспись каждого события Winline |
| `LIGASTAVOK_ENABLED` | авто | Включена ли Лига Ставок. По умолчанию — только если задан `LIGASTAVOK_PROXY` (без «жилого» IP она всё равно отдаёт 0, а браузерный рендер тратит ~50 с каждый цикл). `1` — включить всегда, `0` — выключить всегда |
| `LIGASTAVOK_PROXY` | — | Резидентный российский прокси только для Лиги Ставок: `http://user:pass@host:port` или `socks5://user:pass@host:port`. Qrator жёстко блокирует IP дата-центров (даже московских VPS) — без «жилого» IP эта БК отдаёт 0. Для браузера (Qrator-челлендж) нужен прокси с авторизацией по IP — логин/пароль Chrome не передаёт. Задан прокси — Лига Ставок включается автоматически |
| `LIGASTAVOK_CHALLENGE_WAIT` | `45` | Сколько секунд ждать прохождения Qrator-челленджа Лиги Ставок в браузере |
| `BETBOOM_FEED_TIMEOUT` | `90` | Макс. время сбора всей прематч-линии BetBoom через websocket-фид, сек |
| `BETBOOM_FULL_MARKETS` | `1` | Забирать полную роспись каждого матча BetBoom (все рынки, ~10 МБ трафика на цикл); `0` — только топ-ставки |
| `LIVE_ENABLED` | `1` | Лайв-сканер. `0` — выключить лайв полностью: акцент и все ресурсы CPU/сети — прематчу (полезно на слабом VPS) |
| `SOUND_ALERT_PROFIT` | `2.5` | Порог доходности для звукового уведомления, % |
| `REQUEST_DELAY_MIN` / `REQUEST_DELAY_MAX` | `2` / `5` | Случайная задержка между запросами к одной БК, сек |
| `DB_PATH` | `arbs.sqlite3` | Файл SQLite с историей найденных вилок |
| `FONBET_LINE_HOST` | — | Хост сервера линии Fonbet, если авто-подбор не сработал (напр. `line01w.bk6bba-resources.com`) |
| `BCGAME_API_HOST` | `https://cocoesports.com` | Хост REST-фида BetBy для bc.game (российское «зеркало») |
| `BCGAME_BRAND_ID` | `2103509236163162112` | brand_id BetBy по умолчанию (актуализируется с сайта bc.game) |
| `BCGAME_LANG` | `ru` | Язык линии bc.game (русские названия для сопоставления с БК РФ) |
| `USE_SELENIUM` | `1` | Использовать браузер (Selenium) для динамических БК. `0` — отключить |
| `CHROME_BINARY` | — | Путь к бинарю браузера (напр. `/usr/bin/google-chrome`). Если Chromium из snap не стартует — укажите не-snap Chrome |
| `CHROMEDRIVER_PATH` | — | Путь к chromedriver вручную. Обычно не нужен — сканер подбирает драйвер сам (Selenium Manager) |
| `HTTP_TIMEOUT` | `10` | Таймаут HTTP-запросов к БК, сек |

## Диагностика («почему 0 котировок»)

Запустите `python -m app.diagnose` — покажет IP/страну, доступность Selenium и что отдаёт каждая БК. Частые причины пустого результата:

1. **IP не российский.** Сайты БК доступны только из РФ. Решение — VPS с российским IP. Для Лиги Ставок этого мало: её анти-бот Qrator отклоняет IP **дата-центров** (в т.ч. российских хостингов, проверено на московском VPS — 403-заглушка «доступ ограничен») — нужен «жилой» (резидентный) IP или прокси. Поэтому **по умолчанию Лига Ставок выключена** и включается автоматически, когда задан резидентный прокси `LIGASTAVOK_PROXY` (см. таблицу настроек); для прохождения браузерного челленджа включите у провайдера прокси **авторизацию по IP** вашего сервера. На «жилом» IP без прокси включайте вручную: `LIGASTAVOK_ENABLED=1`. Остальные четыре БК работают без этого.
2. **Не установлен Selenium/Chromium или Chromium из snap не стартует.** Лига Ставок — это SPA, её линия грузится JavaScript'ом, поэтому нужен браузер. Fonbet, Winline и BetBoom работают без браузера (Fonbet — JSON-API, Winline и BetBoom — прямые websocket-фиды линии; нужен `pip install websocket-client`).

   ⚠️ **Chromium из snap (пакет `chromium-browser` на Ubuntu ставится как snap) под systemd часто не запускается** — в логе `Service /snap/bin/chromium.chromedriver unexpectedly exited. Status code was: 1`, и Лига Ставок даёт 0. Скачанный драйвер тоже не может управлять snap-хромом (конфайнмент). Решение — поставить **не-snap** Google Chrome и указать его сканеру:

```bash
cd /tmp
wget -q https://dl.google.com/linux/direct/google-chrome-stable_current_amd64.deb
apt install -y ./google-chrome-stable_current_amd64.deb
snap remove chromium 2>/dev/null; apt-get remove -y chromium-browser 2>/dev/null; true
# указать бинарь в юните (драйвер сканер подберёт сам через Selenium Manager)
echo 'Environment=CHROME_BINARY=/usr/bin/google-chrome' >> /etc/systemd/system/arb-scanner.service
systemctl daemon-reload && systemctl restart arb-scanner
```

   Сканер сам предпочитает не-snap браузер и при сбое явного драйвера откатывается на авто-подбор (Selenium Manager), но исправный не-snap Chrome для этого должен быть установлен.
3. **Сменился домен линии Fonbet.** Домены вида `lineNNw.<hash>.com` периодически меняются. Парсер перебирает известные кандидаты (включая формат `line01w.bk6bba-resources.com`), но если все не подошли — найдите актуальный хост в браузере (DevTools → Network → запрос `events/list`/`events/listBase`) и задайте `FONBET_LINE_HOST`.
4. **Изменилась вёрстка Лиги Ставок или схема фидов Winline/BetBoom.** CSS-селекторы Лиги Ставок в `app/parsers/ligastavok.py` могут потребовать актуализации под текущую разметку; для Winline — номера шагов/полей бинарного фида в `app/parsers/wl_feed.py`, для BetBoom — номера полей protobuf в `app/parsers/bb_feed.py`. Структура парсеров при этом сохраняется.
5. **Слабый VPS: не хватает памяти.** Chrome + сканер требуют ~1.5–2 ГБ. Если в логе процесс внезапно завершается словом `Killed` — это OOM-killer. Добавьте swap (после этого перезапустите сканер):

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile
mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab   # чтобы пережил перезагрузку
```

Рекомендуемый минимум для VPS: **2 vCPU и 2 ГБ RAM** (+2 ГБ swap). На 1 vCPU / 1 ГБ сканер работает, но рендеринг страниц заметно медленнее.

## Важно про парсинг

- Сайты БК доступны **только с российских IP** и активно защищаются от парсинга; вёрстка и домены периодически меняются — это нормально для парсеров БК и иногда требует ручной подстройки.
- Все парсеры отдают двухисходные рынки в едином виде: победитель, тоталы (с предметом — голы/углы/карты/сеты/…), форы (со знаковой линией). Предмет и часть матча приводятся к канону функцией `market_scope` в `app/parsers/html_utils.py`, поэтому один и тот же рынок разных БК сопоставляется независимо от формулировки.
- Парсер **Fonbet** работает через публичный JSON-API линии (без браузера): победитель (921/923), **вся лестница** линий тоталов (930/931, 1696/1697, 1727/1728, 1730/1731, 1733/1734, 1736/1737, 1739/1791, 1793/1794, 1796/1797, 1799/1800, 1802/1803, 1805/1806; тотал очков ракеточных видов 1848/1849), лестница фор (910/912, 927/928, 989/991, 1569/1572, 1672/1675, 1677/1678, 1680/1681, 1683/1684, 1689/1690; фора по очкам 1845/1846), «Обе забьют» (4241/4242), **индивидуальные тоталы обеих команд** (лестницы 1809…1828 — команда 1, 1854…1887 — команда 2; сторона и порядок Больше/Меньше сверены с рынком «Тотал <команда>» BetBoom) и сет-рынки тенниса (тотал сетов 917/918, форы по сетам 2422/2421 и 2424/2425), включая дочерние росписи (тайму/сеты/угловые/карты). Все пары id сверены с теми же рынками Winline/BetBoom на живой линии.
- Парсер **Winline** подключается напрямую к бинарному websocket-фиду сайта (`wss://wss.winline.ru/data_ng`, см. `app/parsers/wl_feed.py`) и забирает **всю** прематч- и лайв-линию без браузера. Снапшот прематча содержит только топ-линии (~10 на матч), поэтому фид дополнительно выкачивает **полную роспись каждого события** командой «event.plus» (как сайт при открытии страницы матча): все линии тоталов и фор, таймы/периоды, «Обе забьют» — в несколько раз больше котировок. Из «экзотики» (src=16) разбираются по белому списку текстов: **индивидуальные тоталы** @1/@2 (весь матч, таймы, периоды/сеты/карты), **чет/нечет**, тотал/фора **2-го тайма** и **фора/тотал по сетам** (теннис). Частота запросов ограничена (`WINLINE_PLUS_RATE`), роспись обновляется по кругу (`WINLINE_PLUS_REFRESH`). Соединение держится постоянно, дельты применяются на лету. При смене протокола правьте номера шагов/полей в `wl_feed.py`.
- Парсер **BetBoom** подключается напрямую к websocket-фиду линии (sporthub, protobuf) и забирает **всю** прематч-линию (несколько тысяч матчей) без браузера. Дерево турниров отдаёт лишь топ-ставки (~7 на матч), поэтому парсер дополнительно подписывается на **полную роспись каждого матча** (`state_subscribe_matches`): все тоталы/форы по всем линиям, таймы/периоды/карты, ЖК, угловые и т.д. — это даёт ~40 000 котировок вместо ~4 000 (отключается `BETBOOM_FULL_MARKETS=0`). При смене схемы правьте номера полей в `app/parsers/bb_feed.py`.
- **Лига Ставок** закрыта анти-ботом **Qrator** (JS-челлендж с proof-of-work на каждый запрос), поэтому **по умолчанию отключена** — включается автоматически при заданном `LIGASTAVOK_PROXY` (или принудительно `LIGASTAVOK_ENABLED=1`). Парсер сначала пробует **внутренний JSON-API** линии (`lds-api-sites.ligastavok.ru`, `POST /rest/events/v8/eventsList`) — сразу, даже без cookie; если Qrator его блокирует — рендерит страницу браузером (Selenium + Chromium), ждёт прохождения челленджа (`LIGASTAVOK_CHALLENGE_WAIT`), переносит полученные Qrator-cookie в HTTP-сессию и повторяет API; последний рубеж — разбор HTML из отрендеренного DOM. **Qrator пропускает только «жилые» российские IP**: с IP дата-центров (проверено на московском VPS) он отдаёт 403-заглушку «доступ ограничен» даже настоящему Chrome — тогда БК отдаёт 0 котировок (в логе будет явное предупреждение с заголовком полученной страницы). Решение — резидентный прокси в `LIGASTAVOK_PROXY`: HTTP-запросы парсера идут через него целиком, браузер — тоже (но только с авторизацией по IP: логин/пароль прокси Chrome не передаёт). Через «жилой» прокси мобильный API обычно отвечает сразу и браузер вообще не нужен. При смене API/вёрстки правьте `app/parsers/ligastavok.py`.
- Парсер **bc.game** работает через публичный REST-фид спортивной платформы **BetBy** (`cocoesports.com` — российское «зеркало» фида, без авторизации): индекс `/api/v4/prematch/brand/<brand>/ru/0` перечисляет версии чанков, из чанков склеивается полная линия (несколько тысяч событий), а справочник рынков `/api/v3/descriptions/.../markets/ru` даёт русские названия. Разбираются победитель/ставка без ничьей, тоталы, форы (в т.ч. по геймам/сетам), «Обе забьют», чет/нечет и индивидуальные тоталы. `brand_id` bc.game периодически меняется — парсер узнаёт актуальный с сайта, а при неудаче берёт `BCGAME_BRAND_ID`. В отличие от БК РФ, фид bc.game доступен и с зарубежных IP.
- Точность сопоставления: события сшиваются по нормализованной паре команд **и кластеру времени начала** (`START_TS_TOLERANCE`, по умолчанию 30 мин) — первый/ответный матчи и мужские/женские пары одних клубов не смешиваются; вилки с доходностью выше `ARB_MAX_PROFIT` (по умолчанию 25 %) отбрасываются как ошибки сопоставления.

## API

| Метод | Описание |
|---|---|
| `GET /api/arbs?min_profit=2` | Текущие прематч-вилки с доходностью ≥ 2 % |
| `GET /api/odds` | Все собранные прематч-матчи и котировки (по всем БК) |
| `GET /api/matches` | Все прематч-события, сгруппированные по матчу (дата, БК, число рынков) |
| `GET /api/live/matches` | То же для лайва |
| `GET /api/match?id=…` | Полная роспись одного матча: все рынки всех БК бок о бок |
| `GET /api/history?limit=100` | История найденных вилок из SQLite |

deploy/
  arb-scanner.service  # systemd-юнит для VPS
